# 财报自动更新

`Update Earnings Data` 全年全天每 5 分钟巡检 `TOP30_COMPANIES` 中的全部公司；新增跟踪公司自动加入巡检，无需另列白名单。美国公司识别 Item 2.02 的 8-K 财报附件、6-K 及正式季报，季度取自报表期间，不把公告日期当成报告期。三星、SK 海力士、腾讯、阿里巴巴另检查官方发布页；其他非美国公司沿用官方 IR 和规范化财务表来源。

新季度优先补入通过期间、单位和数值检查的财务数据，再补正式季报中的分类细项。第三方来源保留自己的来源标记。尚未披露或不能可靠解析的数值保持缺失，不用上一季度或预测数补齐。银行等没有披露营业利润小计的公司，不凭空生成营业利润。

每家公司独立更新。构建报错、仍停在旧季度或校验失败时，恢复该公司的公共数据快照，继续处理其他公司。每轮有时间预算，重试顺序会持久保存，失败的公司不会长期挡住其他公司。缺少已有分类层级时，保留完整的已发布图表，并报出待补项继续重试。

有效更新提交到 main 后显式触发 Pages 发布；部署完成还会重新读取公开地址，核对全部公司的最新季度和核心数值。Cloudflare 数据文件要求重新验证缓存。诊断报告保存在每次 Actions 运行的 artifact 中；未完成的检查会使运行失败，GitHub 通知是否发送邮件由账户的 Actions 通知设置决定。

`Earnings Scheduler Watchdog` 每半小时以及财报/部署任务完成后检查调度，超过 15 分钟没有任务时补触发，避免重复启动正在运行的更新。

这是一套尽快更新和发现漏更的机制，不是秒级 SLA：GitHub 的定时调度可能延迟或丢弃，交易所/发行人可能晚于新闻稿开放完整数据，新的报表版式也可能需要修正解析器。异常会保留旧的有效数据并明确报错，不会冒充成功。

本机只读检查：

```sh
python scripts/watch_earnings.py --dry-run --report-path output/update-report.json
```

在 Actions 手动运行 `Update Earnings Data` 可指定公司；不填写则检查全部。查看报告里的 `failedCompanies`、`deferredCompanies`、`pendingDetails` 和逐公司错误。不要通过清空失败列表或把旧季度标记为已更新来消除错误。


财报图完整性门禁：快速发布必须取得本期营收分类及已有的子分类层级，并核对分类和子分类之和。模板只用于匹配科目名称，本期金额必须来自本期公告，不沿用历史占比。缺项时回滚该公司的本次更新并继续重试，即使公告日期没有变化也重新尝试。覆盖率每次重新计算，不信任旧季度留下的“完整”标记。已存在的缺项季度标为待补全，页面和导出均拒绝生成误导性桑基图；财务总额及营收趋势仍可查阅。正式披露的分类变化允许更换父级，而不强制沿用旧分类。

部署验证同时比较营收分类、子分类、费用分类和同比环比。缺失值保持缺失，不显示为 0%。
